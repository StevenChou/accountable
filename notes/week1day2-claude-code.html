這一天在做什麼

Day 2 是在這個專案裡設定 Claude Code 的工作環境：它要讀哪些說明文件、哪些指令可以不經詢問直接執行、可以使用哪些外部工具和 skill。專案層級的設定會 commit 進 repo，之後任何人 clone 這個 repo，都會拿到同一套設定。

做完之後，repo 會多出 .claude/settings.json、.claude/skills/brand/SKILL.md、.mcp.json，AGENTS.md 也會修改。

指令都在 VS Code 的終端機、accountable 資料夾裡執行。Windows 的終端機是 PowerShell。~ 代表你的家目錄，PowerShell 裡寫成 $HOME。

同一個資料夾裡還有 Codex、GitHub Copilot、Cursor、OpenCode、Pi、Antigravity CLI 的版本，步驟和標題都相同。

名詞解釋

repo
用 git 管理版本的專案資料夾，這裡指 accountable/。
commit
把目前的變更存成一筆版本紀錄。只存在你的電腦上，執行 git push 之後才會上傳。
~（家目錄）
你帳號的個人資料夾。Mac 上是 /Users/你的帳號名稱，PowerShell 寫成 $HOME。
session
從啟動 claude 到離開為止的一段對話。
context window
Claude 在一段對話中能同時看到的內容量。檔案、對話、工具說明都會佔用它。
scope（範圍）
一項設定對誰有效。Claude Code 有 Managed、Local、Project、User 四種，見第 4 步。
settings.json 與 settings.local.json
Claude Code 的設定檔。前者 commit 進 repo，所有人共用；後者只給你自己，不進 git。
permission rule（權限規則）
針對某個動作，規定 Claude 可以直接做（allow）、要先問你（ask），或不准做（deny）。
permission mode（權限模式）
Claude 整體上多常停下來問你。用 Shift+Tab 切換，見第 6 步。
MCP server
讓 Claude 使用外部工具的連接程式。例如 Playwright MCP 讓 Claude 可以操作瀏覽器。
skill
說明某類工作怎麼做的文件（SKILL.md）。平常只有名稱和描述放在 context 裡，需要時才載入全文。
plugin
一個安裝包，可以包含 skill、MCP server、指令等，用 /plugin 安裝和管理。
auto memory
Claude Code 自動把筆記存在 repo 外面，並在下一個 session 載入。課程要求關閉。
AGENTS.md 與 CLAUDE.md
給 coding agent 讀的專案說明。repo 裡沒有 CLAUDE.md 時，Claude Code 才會讀 AGENTS.md。
Markdown
用 #、-、反引號這幾個符號標出標題、清單、程式碼的純文字格式，副檔名是 .md。
漸進式揭露（progressive disclosure）
先給簡短的索引，細節放在別的檔案，需要時才打開。見第 2 步的投影片段落。

投影片

Markdown 與漸進式揭露

Markdown and progressive disclosure — Keep AGENTS.md short and point to the files the agent needs

投影片的副標題是重點：讓 AGENTS.md 保持簡短，裡面寫出 agent 需要的檔案在哪裡，內容留在那些檔案裡。下面分三段說明：漸進式揭露是什麼、AGENTS.md 每一段在做什麼、投影片右邊的四個寫法建議。

一、漸進式揭露是什麼

漸進式揭露（progressive disclosure）的意思是：先給一份簡短的索引，細節放在別的檔案，需要時才打開。類似查一本手冊：先看目錄，知道每一章講什麼、在哪一頁，要用到哪一章才翻過去，不用先把整本讀完。

放到 Claude Code 裡，分成兩層：

第一層：每個 session 都讀
AGENTS.md12 行，359 字元

session 開始時，整份放進 context。相當於手冊的目錄。

Claude 看第一層寫的用途，判斷現在要不要打開下面哪個檔案
第二層：需要時才打開
檔案什麼時候需要字元數
docs/intent.md要知道這個產品要做什麼7,335
docs/TECH_STACK.md寫程式、選套件、跑測試1,660
docs/BRAND.md做 UI（第 9 步已改成 skill）1,444
docs/STATUS.md要知道做到哪裡；做完一段工作後更新32
course/for_agents/（4 個檔案）學生需要課程上的協助67,199
合計 8 個檔案77,670

每個 session 固定讀的是 359 字元。其他 8 個檔案共 77,670 字元，只有用到時才讀，而且通常只讀其中一兩個。如果把這些內容全部寫進 AGENTS.md，每個 session 一開始就要讀 78,029 字元，大部分和當下的工作無關。

字元數是 2026-11-19 用 wc -m 量的。context 實際用 token 計算，數字會不同；這些檔案都是英文，各檔案之間的比例差不多。

二、AGENTS.md 是純 Markdown

Markdown 是一般的文字檔，用幾個符號標出結構：# 是標題、## 是下一層標題、行首的 - 是清單的一項、反引號 ` 包住的是程式碼或路徑。不需要特殊工具，任何編輯器都能改，各家 coding agent 都讀得懂。

這是第 2 步時 AGENTS.md 的全文。第 9 步刪掉了第 9 行的 docs/BRAND.md，下面的行號和字元數都是刪除前的：

AGENTS.md
# Accountable

SIDENOTE: this repo is part of a course by Ed Donner. If the student needs help, read `course/for_agents/`

## Where to find things

- `docs/intent.md`: what we're building
- `docs/TECH_STACK.md`: the stack
- `docs/BRAND.md`: the look, for UI work
- `docs/STATUS.md`: what's done so far

Update `docs/STATUS.md` when you finish a piece of work

逐段說明：

  1. 第 1 行# Accountable標題，寫專案名稱。
  2. 第 3 行SIDENOTE: …說明這個 repo 屬於 Ed Donner 的課程，學生需要協助時去讀 course/for_agents/。這一行也是「指向其他檔案」：那 4 個檔案共 67,199 字元，平常不讀。
  3. 第 5–10 行## Where to find things四個清單項目，格式都是「路徑: 一句用途」。Claude 看用途決定要不要打開，例如 the look, for UI work 表示做 UI 時才需要讀 docs/BRAND.md。
  4. 第 12 行Update docs/STATUS.md …一條動作指示：完成一段工作後，更新 docs/STATUS.md。

三、四個寫法建議（Pro tips）

  1. 1
    寫清楚、寫簡短
    Be clear and concise — The agent reads it every session

    agent 每個 session 都讀整份檔案。多寫一行，每個 session 的 context 就多佔一行；寫得模糊的句子，agent 每次都得自己猜意思。

    改寫前Please try to keep the project docs up to date where appropriate.請在適當的時候盡量更新專案文件。沒說什麼時候、哪一份。
    改寫後Update docs/STATUS.md when you finish a piece of work寫明時機（完成一段工作）和檔案（docs/STATUS.md）。這是 AGENTS.md 的最後一行。

    補充 Claude Code 文件建議每份 CLAUDE.md 在 200 行以內：超過會佔更多 context，Claude 照著做的程度也會下降，啟動時和 /status 會顯示警告。AGENTS.md 在這個 repo 扮演同樣的角色，第 9 步之後是 11 行、318 字元。

  2. 2
    多寫「要做什麼」，少寫「不要做什麼」
    Favor positives over negatives — Say what to do

    只寫「不要做 X」，agent 知道 X 不能用，但不知道該用什麼，只能自己挑一個替代做法。直接寫出要用的做法，agent 照著做就好。真的要禁止某件事時，把替代做法寫在同一句。

    改寫前Don't use pip.不要用 pip。那要用什麼，沒有寫。
    改寫後Use uv for Python: `uv run` and `uv add`, never `pip install`.先寫要用的指令，最後才補一句不要用什麼。這是第 3 步的範例句。
  3. 3
    指向其他檔案
    Point to other files — Opened only when needed

    AGENTS.md 只放路徑和一句用途，細節留在原本的檔案。agent 用到時才打開，用不到的檔案不佔 context。

    改寫前把 docs/TECH_STACK.md 的 26 行全文貼進 AGENTS.md每個 session 多讀 1,660 字元，包括做 UI、寫文件這些用不到技術棧的工作。
    改寫後- `docs/TECH_STACK.md`: the stackAGENTS.md 只多一行，全文在需要時才讀。
    注意 補充

    路徑前面不要加 @。在 CLAUDE.md 和 AGENTS.md 裡，沒有用反引號包住的 @docs/intent.md 是匯入語法：session 開始時就把整份檔案載入，又變回每次都讀。只有確定每次都要整份載入的檔案才用 @，例如本步驟前面給舊版 Claude Code 用的 @AGENTS.md。

    第 9 步把 docs/BRAND.md 改成 skill，是同一個做法：context 裡只留 skill 的名稱和一行描述，做 UI 時才載入全文。

  4. 4
    實際測試
    Experiment — Watch what your agent does

    寫下的指示，agent 不一定照你預期的方式使用。改完 AGENTS.md 之後，拿實際的問題測試，看它讀了哪些檔案。

    1. AGENTS.md 在 session 開始時載入。改完後離開 Claude Code，重新執行 claude。
    2. 執行 /memory，確認清單裡有 AGENTS.md 的路徑；/context 可以看它佔了多少 context。
    3. 問一個要讀某份文件才答得出來的問題，看 Claude 回答前讀了哪些檔案。畫面上的工具呼叫會顯示 Read 和檔名。
    4. 沒有讀到預期的檔案，就改 AGENTS.md 裡那一項的用途說明，再測一次。
    可以這樣問預期它打開
    Accountable 的 MVP 有哪幾個區塊？docs/intent.md
    跑測試要用什麼指令？docs/TECH_STACK.md
    專案目前做到哪裡了？docs/STATUS.md

權限

Permissions
完成
要做什麼

執行 /permissions，加入下面三條規則，每一條都存到 project settings：

  • AllowBash(npm test)執行測試不用問你。docs/TECH_STACK.md 寫明測試使用自己的資料庫，不會改到你的資料。
  • AskBash(git push *)任何 git push 都先問你，因為 push 會把 commit 上傳到 GitHub。
  • DenyRead(./.env)禁止讀 .env，這個檔案放的是 API key 這類密碼。

.claude/settings.json 會變成這樣：

.claude/settings.json
{
  "permissions": {
    "allow": ["Bash(npm test)"],
    "ask": ["Bash(git push *)"],
    "deny": ["Read(./.env)"]
  }
}
檢查順序deny→ask→allow

Claude Code 先檢查 deny 規則，再檢查 ask，最後才是 allow。deny 規則在每種模式都有效，ask 規則在 Auto 模式下也照樣會問。在 Auto 模式下，讓 agent 能執行任意程式碼的大範圍 allow 規則會被擱置，例如 Bash(npm run *) 或 Bash(uv run *)；Bash(npm test) 這種範圍窄的規則則保留。

權限模式（按 Shift+Tab 依序切換）
Auto你目前的模式

預設模式。Claude 不逐一詢問就工作，背景有另一個模型審查 shell 指令、網路請求這類動作。

Manual

編輯檔案和執行指令前都會問你。舊資料稱為「default mode」。

Accept edits

編輯檔案和簡單的檔案指令直接執行，其他指令會問。

Plan

Claude 只讀取和規劃，你核准計畫之前不做任何修改。

另外兩種模式 Don't ask 和 Bypass permissions 用於自動化和容器，預設不在 Shift+Tab 的循環裡。只有用 --allow-dangerously-skip-permissions 這類旗標啟動 Claude Code 時，Bypass 才會加入，排在 Plan 之後。

白話說明

npm run 後面可以接任何 script，允許它等於允許執行任意程式，所以 Auto 模式不採用這種規則。npm test 只會執行固定的測試指令，範圍明確。

三條規則存到 project settings，commit 之後，repo 裡的每個人都套用同樣的限制。
