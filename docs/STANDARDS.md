# Accountable 程式撰寫標準

- **讓變更容易讀懂。** 改動限於當次需求，沿用現有模組、元件和相依套件。用能說明用途的名稱，讓讀者容易找到執行規則的位置。共用業務規則集中維護，例如表單和看板沿用同一套商機階段轉換規則。
- **讓規格和行為一致。** 改變使用者看得到的行為時，依 [規格索引](spec.md) 同步更新受影響的區域規格、共用規則及驗收條件。產品範圍或文件入口有異動時，也要更新索引。沿用現有 API 契約，並在後端驗證寫入資料與業務規則。
- **讓型別描述實際資料。** 前端維持 TypeScript 的嚴格型別，API 輸入和回應使用明確型別。遇到空值或格式差異時明確處理，避免用 `any` 或型別斷言掩蓋不符的資料。後端沿用 Pydantic 驗證輸入，使用 SQLAlchemy Core 存取資料。
- **處理失敗並保護資料。** 相關寫入應在同一筆交易完成，例如跨欄移動商機時，一起儲存階段、順序和活動。表單儲存失敗時保留輸入，提示使用者可採取的動作。憑證、個人資料及日常資料庫不得提交到 Git。
- **沿用介面慣例。** 介面文字採繁體中文，金額使用 `NT$`。表單欄位加上清楚的標籤，按鈕、連結及其他互動元件須能用鍵盤操作。
- **驗證改動的行為。** 變更行為時，用現有測試套件驗證正常和相關失敗情境。修正行為錯誤時，保留能重現原問題的回歸測試。測試一律使用範例或虛構資料，資料庫測試使用獨立的暫存 SQLite。
