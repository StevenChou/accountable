# Accountable MVP 設計規格

## Concerns

- **已確認的刪除規則。** 刪除聯絡人或商機時，確認視窗列出受影響的活動及未完成跟進筆數。確認後連同附屬活動一併刪除。刪除公司時保留原有聯絡人、商機及其活動，並清除所屬公司連結。
- **採用的業務預設。** 階段預設成交機率為 10%、25%、50%、75%、100% 和 0%。這些是新增與換階段時的起始值，使用者可依個別商機調整。成交統計採最近六個日曆月，即將到期的跟進採未來七天，全部未完成跟進仍可在儀表板查到。
- **品牌與離線操作。** 看板有六個階段，品牌有五個系列色，成交欄使用品牌墨色 Midnight。所有階段都顯示文字名稱。字型隨應用程式提供，繁體中文字使用本機系統字型。
- **驗收環境。** 本次 MVP 在使用者的 Mac 上以 Google Chrome 驗收，同時保留 Linux 和 Windows 的相容目標。

## 目標與適用範圍

Accountable 是給一位兼任業務的小型企業老闆在自己電腦上使用的 CRM。使用者從儀表板查看近期客戶往來與待跟進事項，開啟相關聯絡人或商機的時間軸，記下下一步。其餘工作透過公司、聯絡人、商機與商機看板進行。範圍依 [產品意圖](intent.md) 的限制與後續待議，包含登入、多人共用、操作者紀錄及從其他電腦存取等事項都留待後續決定。

## 選定設計

採用 **A · 跟進工作台**。它把待跟進事項和近期活動放在首頁最上方，方便使用者先找出逾期事項，再回顧最近的客戶往來。 [HTML 設計稿](mockups/1-follow-up.html) · [儀表板截圖](mockups/1-follow-up-dashboard.png) · [商機看板截圖](mockups/1-follow-up-pipeline.png)

- **儀表板**上方左側是待跟進事項，右側是近期活動。下方依序顯示成交與進行中商機摘要、每月成交金額折線圖與成交筆數長條圖，以及各階段商機金額。
- **商機看板**上方橫列顯示進行中商機筆數、合計金額與預期營收。下方是六個階段欄，欄首顯示該階段的統計並提供新增商機入口。較窄的筆電畫面可在看板區內橫向捲動。

## 共用介面與行為

- 頂端橫向導覽連到五個功能區塊，首頁為儀表板。各區塊與公司、聯絡人、商機的詳情頁都有自己的網址，重新整理可回到同一頁，並支援瀏覽器上一頁與下一頁。已刪除的紀錄顯示說明與返回列表的入口。
- 公司、聯絡人和商機列表都提供搜尋、新增及可按欄名切換升降冪的資料欄。每列可開啟詳情、編輯或刪除。搜尋忽略前後空白與英文字母大小寫，對各列表指定的欄位比對部分文字。空列表與沒有搜尋結果分別顯示原因。
- 表單標示必要欄位，驗證失敗時顯示欄位提示。儲存失敗時保留輸入，刪除失敗時保留原紀錄。讀取失敗時顯示原因與重試入口，統計資料未取得時顯示讀取狀態。已成功儲存的變更會反映在相關頁面。
- 依 [品牌規範](../.claude/skills/brand/SKILL.md) 使用淺色背景 `#F0F4F5`、白色圓角面板與 Midnight `#073B4C` 內文。主要操作用 Sea Green `#06D6A0` 搭配 Midnight 文字。逾期標示使用品牌警示色和「逾期」文字，文字與背景需有足夠對比。
- 標題及內文用 Instrument Sans，數字用 JetBrains Mono。繁體中文回退至本機系統字型。導覽、欄名、表單、驗證訊息與圖表均用繁體中文，金額加上 `NT$` 並使用千分位。筆電與桌機使用同一套操作，畫面依選定的設計稿製作。

## 資料與關聯

| 紀錄 | 欄位與規則 |
| --- | --- |
| 公司 | 名稱必填，網站、產業、備註可留空。可連結多位聯絡人和多筆商機。 |
| 聯絡人 | 姓名及狀態必填。電子郵件、電話、職稱和所屬公司可留空。狀態為潛在客戶、已確認、既有客戶，新增預設為潛在客戶。 |
| 商機 | 名稱、階段、金額和成交機率必填。公司、主要聯絡人和預計結案日可留空，已結案商機須有實際結案日。金額為非負的新臺幣，可輸入至小數兩位。成交機率為 0 至 100 的整數百分比。 |
| 活動 | 各自隸屬一位聯絡人或一筆商機。包含類型、內容和發生時間，可加上跟進日期與完成狀態。手動類型為備註、通話或電子郵件，發生時間預設為現在。系統會另行產生商機階段變更活動。 |

關聯紀錄使用識別碼連結。日期以本機日曆日判斷與呈現，活動時間轉為本機時間顯示。金額以整數分儲存，避免統計受到浮點精度影響。

### 刪除規則

| 刪除對象 | 確認視窗與資料結果 |
| --- | --- |
| 公司 | 顯示會解除連結的聯絡人與商機筆數。保留這些紀錄及其活動，清除其所屬公司連結。 |
| 聯絡人 | 顯示會解除主要聯絡人連結的商機筆數，以及會刪除的活動總數與其中未完成的跟進筆數。保留相關商機與商機自己的活動。 |
| 商機 | 顯示會刪除的活動總數與其中未完成的跟進筆數，包含該商機的階段變更活動。保留公司和主要聯絡人。 |
| 手動活動 | 說明會刪除活動，若有未完成的跟進，也會從儀表板的待辦清單移除。 |

取消確認時資料保持原狀。確認後，在同一次資料庫交易內刪除紀錄並處理關聯。成功後更新相關列表、時間軸、看板與儀表板統計。

## 五個功能區塊

### 儀表板

- 首頁優先顯示待跟進事項與近期活動。未完成且有跟進日期的活動都列入待辦，依本機日期分為逾期、今天到期、未來七天內到期和稍後到期，按此順序排列，各組依到期日由早到晚。完成後即移出待辦，原活動保留於時間軸。
- 近期活動顯示最新 10 筆，包含手動活動與系統產生的階段變更，依發生時間由新到舊排列。待辦和近期活動顯示關聯紀錄、內容摘要與日期，可直接開啟該聯絡人或商機的時間軸。可在待辦清單標記完成。
- 成交摘要顯示本月成交筆數與金額。折線圖呈現最近六個日曆月的每月成交金額，長條圖呈現同期成交筆數，包含本月及零成交月份。階段視覺化依看板欄序呈現六個階段的商機金額，各階段顯示名稱與金額。
- 進行中摘要顯示商機筆數、合計金額與預期營收。階段變更、金額調整或刪除商機後，重新依已儲存資料計算。新增、完成或刪除跟進後，待辦清單同步更新。

### 公司

- 列表顯示名稱、網站與產業，可搜尋名稱與產業。詳情頁顯示全部公司欄位，並列出可點開的所屬聯絡人和商機。

### 聯絡人

- 列表顯示姓名、所屬公司、職稱、電子郵件、電話與狀態。可搜尋姓名、公司與聯絡方式，並以全部、潛在客戶、已確認或既有客戶篩選。搜尋與狀態篩選可同時使用。
- 詳情頁顯示完整資料、所屬公司連結及活動時間軸。使用者可記錄備註、通話或電子郵件並安排跟進。

### 商機

- 列表顯示名稱、公司、主要聯絡人、階段、金額、成交機率和結案日期，可搜尋名稱、公司或主要聯絡人。詳情頁顯示完整資料、關聯公司及聯絡人的連結，以及商機的活動時間軸。
- 新商機、已確認、提案、議價屬於進行中，顯示預計結案日。成交及失單屬於已結案，顯示實際結案日。進行中的商機若預計結案日早於今天，列表與看板卡片都顯示「逾期」。未填預計結案日或當天到期的商機依原狀態顯示。
- 在商機表單儲存階段變更時套用新階段預設機率，即使同一次送出包含原本的手動機率。使用者可在新階段存妥後再調整機率。一般編輯與同欄排序保留已存機率。商機階段與聯絡人狀態各自編輯。
- 進行中的商機移到成交或失單時，實際結案日預設為今天，之後可在表單修正為今天或更早的日期。已結案商機在成交與失單之間移動時保留其實際結案日。重新開啟時清除實際結案日，沿用先前的預計結案日（若有），並依新階段套用預設機率。

### 商機看板

| 欄序 | 階段 | 預設成交機率 | 品牌色 |
| --- | --- | --- | --- |
| 1 | 新商機 | 10% | Sea Green `#06D6A0` |
| 2 | 已確認 | 25% | Marigold `#FFC145` |
| 3 | 提案 | 50% | Coral `#F78C6B` |
| 4 | 議價 | 75% | Cerulean `#118AB2` |
| 5 | 成交 | 100% | Midnight `#073B4C` |
| 6 | 失單 | 0% | Raspberry `#EF476F` |

- 卡片顯示商機名稱、公司、金額、成交機率、結案日期及逾期標示，連到詳情頁。每欄可新增商機，新表單以該欄階段和預設機率起始。新增時如果直接選擇已結案階段，實際結案日預設為今天。
- 欄內任意位置都可放置卡片，含首位、末位及空欄。同欄拖放只儲存順序。跨欄拖放同時儲存目標位置、階段、預設機率、結案日期變更與一筆系統活動。從表單新增商機或更換階段時，預設放在目標欄的第一位。儲存成功後，重新整理或重新啟動會顯示相同的順序。
- 看板整體與各欄顯示進行中商機合計金額和預期營收。成交與失單欄顯示階段筆數，該欄的進行中合計也以 `NT$0` 表示。拖放成功後立即更新統計與列表。若儲存失敗，卡片回到原位置並顯示錯誤。

## 活動與統計規則

- 聯絡人或商機的時間軸依發生時間由新到舊顯示該紀錄的活動。每筆顯示內容、類型、發生時間和跟進日期及狀態（若有）。使用者可新增、編輯、刪除手動活動，也可從時間軸標記跟進完成。移除跟進日期會將該項移出待辦。
- 每次實際變更既有商機的階段，包含表單變更、跨欄拖放、成交、失單與重新開啟，寫入一筆「從提案移至議價」這類的系統活動。系統活動保留原始內容直到商機刪除。
- **每月成交。** 依目前階段為成交的商機之實際結案日歸入日曆月，分別計算筆數與金額總和。商機重新開啟後，對應月份的數字隨之更新。
- **進行中商機。** 以四個進行中階段計算筆數和金額總和。預期營收為 `Σ（商機金額 × 成交機率 ÷ 100）`。各統計範圍先加總，再四捨五入至新臺幣小數兩位。例如 `NT$100,000 × 25% + NT$50,000 × 50% = NT$50,000`。
- **各階段金額。** 儀表板的階段視覺化分別加總各階段的商機原始金額，含成交與失單。看板合計使用進行中商機的定義。

## 本機架構與範例資料

- React 頁面由 FastAPI 的本機 JSON API 取得資料。API 提供公司、聯絡人、商機與活動的讀寫，以及看板、儀表板彙整。後端依 [技術堆疊](TECH_STACK.md) 使用 SQLAlchemy Core 存取本機 SQLite。欄位、外鍵與階段規則在後端驗證，失敗時前端顯示可採取行動的訊息。
- 看板移動傳送商機、目標階段及插入點卡片的識別碼。後端將移動的卡片放在插入點卡片之前，省略插入點時放在欄末。後端在一筆交易內更新受影響欄位、順序及活動，儲存成功後前端更新受影響的資料與統計。同一套階段變更規則用於表單與看板。
- 第一次啟動時以虛構的公司、人物和業務情境建立範例資料。內容包含多個產業、三種聯絡人狀態、六個商機階段、近幾個月的成交與失單、未來幾個月預計結案及已逾期的商機，並提供備註、通話、電子郵件及今日、逾期、即將到期和已完成的跟進範例。日期相對於初始化當天產生。正常重啟沿用既有資料，包括使用者清空的列表。
- 備妥工具與相依套件後，`npm run dev` 同時啟動前後端。字型與前端資源由本機提供，瀏覽器開啟與日常操作皆可離線。`npm run seed` 會清除現有本機資料並恢復範例資料，操作文件須說明這個效果。啟動與重設指令的使用方式於建置後記錄在 [專案進度](STATUS.md)。

## 驗收條件

下表對應 [產品意圖的八項成功標準](intent.md#成功標準)。

| 編號 | 驗收方式 |
| --- | --- |
| 1 | 預先安裝相依套件後，在 Mac 斷網執行 `npm run dev`，從 Chrome 開到儀表板，確認五個區塊皆有範例資料且可操作。 |
| 2 | 在公司、聯絡人和商機各新增一筆，依關鍵字查找、切換欄位排序、編輯並刪除。取消一次確認，再驗證確認視窗所列的筆數與實際關聯變更。重新整理及重啟確認變更保留，執行 `npm run seed` 後確認範例資料恢復。 |
| 3 | 逐一切換聯絡人的三種狀態篩選。開啟公司查看旗下聯絡人與商機，再從聯絡人和商機詳情開啟已存在的關聯。 |
| 4 | 將手動調整過機率的商機拖到另一欄，確認階段和預設機率出現在列表，並確認看板與各欄統計立即更新。在同一欄及跨欄拖到首、中、末位置，含放入空欄，重新整理後比對順序。從指定欄新增商機，並在列表和卡片上看到逾期標示。 |
| 5 | 在聯絡人和商機的時間軸新增、編輯及刪除手動活動，確認由新到舊排序。以表單和拖放變更階段，每次各出現一筆系統活動。檢查待辦日期分組，包含今天、第七天和第八天的邊界。標記完成後從待辦移除，時間軸仍保有活動。 |
| 6 | 從儀表板點入一次聯絡人或商機時間軸並新增跟進，回到首頁查看結果。使用已知金額與機率核對預期營收，再將商機標為成交，確認當月成交筆數、金額與進行中合計反映變更。 |
| 7 | 逐頁目視檢查淺色介面、繁體中文、品牌色及 `NT$` 金額。從圖表名稱和數值確認折線圖、長條圖與六階段視覺化的指標，並在筆電寬度檢查可操作性。 |
| 8 | `npm test` 通過後，在 Mac 上以 Chrome 從儀表板走訪五個區塊，依日常業務流程實際做一遍上述操作，逐頁檢查畫面，確認瀏覽器主控台無錯誤。 |

`npm test` 包含 Vitest 前端單元測試、pytest 後端單元測試與 Playwright Test 的 Chrome 端對端測試，任一測試失敗時命令須回報失敗。測試自行啟動必要的服務並使用獨立資料庫。
