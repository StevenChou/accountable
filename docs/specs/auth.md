# 登入與存取

## 正式帳號

- 管理者在 Supabase 控制台以 Email 建立帳號，自行註冊關閉。登入表單提供 Email、密碼與「登入」按鈕。成員使用 Supabase Auth 登入。
- 所有已授權成員可讀寫同一份公司、聯絡人、商機與活動資料。成員角色、個別操作權限、社群登入、魔法連結及自助重設密碼屬於本版範圍之外。

## 頁面與登入狀態

- 未登入時，開啟儀表板、列表、紀錄詳情、看板或未知的應用程式路徑，皆顯示登入畫面。驗證期間顯示載入狀態，確認有效登入後才顯示 CRM 內容。
- 登入成功後開啟目前網址對應的頁面。從根網址登入會顯示儀表板，從紀錄網址登入會開啟該紀錄。重新整理時，有效的登入狀態可繼續使用。登入失敗留在表單，顯示可重試的訊息，帳密錯誤採共用提示。
- 從使用者選單選擇「登出」後，清除目前瀏覽器的登入狀態與畫面上的 CRM 資料，回到登入畫面。若登入狀態已失效，應用程式也回到登入畫面。按瀏覽器上一頁或直接輸入紀錄網址時，仍須通過登入驗證。
- 登入表單、驗證提示與登入狀態使用繁體中文，欄位與按鈕可用鍵盤操作，畫面套用共用主題。[品牌規範](../../.claude/skills/brand/SKILL.md)

## API 驗證

- 正式模式的瀏覽器使用 Supabase Project URL 與 publishable key 設定 Supabase Auth。每次呼叫受保護的 CRM API 都隨請求提供登入權杖。FastAPI 驗證權杖並從驗證後的權杖識別成員。
- API 對缺少、無效或已過期的權杖回傳 HTTP 401，阻止讀寫 CRM 資料。公司、聯絡人、商機、活動、看板、儀表板及全站搜尋均套用同一規則。寫入的操作人由後端依已驗證的身分決定。
- CRM 資料透過 FastAPI 存取。Supabase 公開資料 API 的 CRM 資料表以資料列層級安全性（RLS）限制存取，瀏覽器用公開設定或成員權杖直接呼叫該 API 時，無法越過 FastAPI 直接讀寫 CRM 資料。
- 本機開發和測試使用虛構使用者，提供相同的登入與登出狀態、受保護頁面及 API 行為，可切換成員驗證共用資料和操作人。[執行模式與部署](runtime.md)
